# 智排（智能路由）——一种通用解决方案

> 这是一份**独立、通用的思路介绍**，不绑定任何特定项目/代码。
> 讲的是一套「按任务复杂度动态选模型」的做法，核心是**省钱**，
> 同时尽量少牺牲回答质量。任何接入多模型的应用都能套用。

## 一句话

智排 = 每次提问，先**用一套启发式规则判断这题是「简单」还是「复杂」**：简单 → 用**本地免费**的模型；复杂 → 才动用**云端付费**的模型。让钱只花在真正需要的地方。

## 解决什么问题

接入云端大模型后，成本几乎和 token 数量成正比。但现实中：

- 大量对话是**短、指令式**的（改个词、解释一句话、续写），简单模型完全能答；
- 只有少数是**重活**（写代码、多步骤、深度分析、看图）。

如果一律用最强（最贵）的模型，就相当于用小货车运所有包裹——大部分成本被浪费在简单任务上。

**智排的思路**：给每次提问分个级，把简单任务导到便宜（甚至免费）的通道，只有复杂任务才走贵通道。

## 适用场景建议

这套方案**不是所有场景都值得开**，收益最大的条件是：

- **你手头有一个可靠的本地免费模型**（且真的在跑）——否则「简单通道」形同虚设，反而因兜底更费钱。
- **重活占比低**：多数是短问答/续写，少数是写代码或深度分析。重活占绝大多数时，路由省不下多少，收益感不明显。
- **对成本敏感**，愿意为省钱接受简单任务偶尔质量略降。
- **有本地算力**：能跑一个不拖慢体验的本地模型（激活参数小的 MoE 在消费级显卡即可）。
- 反之，若**本地模型常崩、重活占比高、或对质量零容忍**，收益会被「兜底费用 + 质量风险」抵消，这时建议关掉或把阈值调松。

> 一句话：**本地算力够 + 轻量任务居多 + 在意成本 → 值得开；否则先搞定本地模型稳定性再开。**

## 本机环境对照（实测）

当前这台机器恰好是「值得开」的标杆配置：

| 项 | 实测 | 对智排的意义 |

| 云端兜底 | DeepSeek 系（`api.deepseek.com`）：`deepseek-v4-flash`（默认兜底/简单升级）、`deepseek-v4-pro`（超强推理）、`deepseek-v4-flash-vision-exp`（云端视觉） | 复杂通道 + 本地全挂时的最后兜底 |

> 提醒：本地模型未启动时（如 8080~8098 现状），不要把简单通道配到死端口——否则每次都触发云端兜底，反而更贵。

## 怎么给任务分级

每次提问做一次判断，**关键词的优先级高于长度**。一个常见的判定顺序：

1. **带图片/文档等非文本内容** → 直接判复杂（本地模型多模态弱，硬上会翻车）
2. **空文本** → 判简单（多半是工具链续步，用便宜的）
3. **含代码块** → 判复杂
4. **命中强关键词**（设计 / 架构 / 重构 / 调试 / 排查 / 根因 / 优化 / 性能 / 安全 / 为什么 / 如何实现 / 逐步 …）→ 判复杂
5. **≥2 个段落**（描述较繁琐）→ 判复杂
6. **超出长度阈值**（如 160 字 / 28 词，中文按无空格折算）→ 判复杂
7. **弱信号区**（接近阈值但没强信号）→ 拿不准时，可以再让一个「便宜的判定模型」说一句「简单/复杂」

> ⚠️ **不是只按字数。** 关键词和附件优先级更高。一句话「帮我重构这个模块」「这个死锁怎么排查」哪怕很短，也会因命中关键词走贵模型。按字数只是兜底手段。

## 为什么省

把「简单通道」接到一个**本地/免费模型**上，而「复杂通道」才用云端付费模型：

- 大多数日常短问答 → 免费本地模型 → **这部分成本 ≈ 0**
- 真正的重活 → 云端付费模型 → **钱只花在这里**

大头开销被挡在本地模型之外，这就是省钱的原理。

## 落地建议（按性价比排序）

1. **简单通道必须指向在跑的本地模型。** 如果配置的本地端口/服务没启动，本地打不通，系统往往会**自动切云端兜底**——反而更贵。所以：哪个本地模型真正在跑，简单通道就配哪个。

2. **长度阈值别太保守。** 中文本就常是短句，若阈值偏小，简单任务会被误判成复杂。可以**先调大**（把更多轮次留在本地），观察质量；若简单模型常答错，再回退。

3. **强模型能换本地就换本地。** 如果机器能跑一个够强的大模型（activated-params 小的 MoE 在消费级显卡上就能跑），把复杂通道也指到本地 → 复杂任务也免费。这是**最狠的省钱**，代价是要求本机算力。例如 **2× RTX 2080 Ti 22G**（合计 ~44GB 显存）即可承载 30B+ 级 MoE 量化模型——本机实测正是双 2080 Ti 22G 在跑 35B 本地模型。这种「本地模型同时担任简单通道与复杂通道」的形态，就是完整的**本地级联**：级联的三层（简单→复杂→仲裁）全部免费。

4. **兜底模型也要挑。** 智排不命中时的默认模型，若是云端付费，意味着「没分级到的轮次」也在花钱。想尽量免费，就把它也指向本地；想保底聪明，就保留云端。

5. **弱信号区用本地模型仲裁。** 拿不准时花一次免费本地调用问「简单还是复杂」，准确率提升换来的是**避免把复杂任务误判到便宜模型**，往往比省下的 token 划算。建议保持开启。

## 一句话总结

> 智排是**「能本地就本地，搞不定才上云端」的闸门**，本质是一条**级联**管道：简单任务走本地（免费）、复杂任务走更强模型（配置够强时可仍在本地）、拿不准用本地模型仲裁（免费）——层层往下只在你真正需要时才触达付费层。**确保简单通道指向真正在跑的本地模型**，是这套方案最关键的杠杆。

## 取舍提醒

- **省钱 ↔ 质量**：阈值越松（更多任务走本地）越省，但本地模型答不了复杂题时质量会掉。按你的实际内容调节。
- **稳定性 ↔ 成本**：本地出错自动切云端兜底，更稳、但可能意外产生云端费用。若本地模型常崩，兜底成本会上升。
- **把本文当「一套可选方案」**：它只是众多模型调度策略之一；按你的使用场景（重活占比、机器算力、对质量的容忍度）决定要不要用、用到多激进。

## 业内名称对照

这个方向在业界已有成熟叫法和专门研究。你实现的其实是下面几个概念的组合。

| 本文的做法 | 业内名称 | 说明 |
|---|---|---|
| 每次提问按复杂度选不同模型 | **LLM Routing / Model Routing**（模型路由） | 通用词：给每个请求决定走哪个模型。LMSYS 的 **RouteLLM**（2024）就是这个方向，在强/弱模型间自动路由、省成本 |
| 简单先走便宜/免费模型，复杂才升级 | **LLM Cascading**（模型级联） | 经典论文 **FrugalGPT**（2023）：小模型先答，不够好再升级到更大模型，显著降本 |
| 拿不准时用一个「判定模型」说简单/复杂 | **Classifier Router**（分类器路由） | 一个轻量分类器或小模型充当路由器，判完再把请求分发给对应模型 |
| 本地便宜 + 云端好模型混用 | **Local-Cloud Hybrid Inference / 混合推理** | 本地能答就本地（省钱/隐私），不够就「溢流 / offload」到云端 |
| 低置信度才升级 | **Escalation / Cost-aware routing**（成本感知路由） | 相同思路的不同叫法 |

**最贴的两个名字**：

- **FrugalGPT** —— 「先用便宜模型，不行再升级」的级联思路；本文的「先本地后云端 + 仲裁」就是它的一个落地变体。
- **RouteLLM** —— 「用规则或训练在强弱模型间一键路由」的框架；与本文的「关键词 + 长度启发式分流」是同一类目标（省成本保质量）。

> 注：本文偏**启发式规则**（关键词、长度、附件），FrugalGPT / RouteLLM 偏**置信度打分或训练路由器**。规则版好处是零训练、可解释、即时生效；代价是不如学习型精准。

## 参考实现（Python，单文件可直接运行）

仅依赖 `requests`，对接任意 OpenAI 兼容端点（本地 vLLM/llama.cpp 服务与云端同构）。
逻辑与上文一一对应：`classify` 判定序 → `resolve` 级联塌缩 → `_arbitrate` 本地仲裁。

```python
# 智排参考实现（Python 3.10+）
import hashlib
import re
import requests

SIMPLE, STRONG, UNSURE = "simple", "strong", "unsure"

STRONG_EN = re.compile(
    r"\b(plan|design|architect|refactor|debug|investigate|analyze|analysis|"
    r"optimi[sz]e|implement|security|performance|deadlock|race|memory leak|"
    r"root cause|troubleshoot|migrate|audit|step by step|how to)\b", re.I)
STRONG_ZH = ("规划", "设计", "架构", "重构", "调试", "排查", "分析", "根因", "为什么",
             "如何实现", "怎么实现", "怎么解决", "优化", "性能", "安全", "漏洞",
             "死锁", "并发", "迁移", "评估", "审计", "逐步", "实现一个", "完整实现")

def contains_han(s: str) -> bool:
    return any("\u4e00" <= ch <= "\u9fff" for ch in s)

def paragraphs(s: str) -> int:
    sep = "\n" if contains_han(s) else "\n\n"  # 中文常单换行分段
    return len([p for p in s.split(sep) if p.strip()])

def classify(text: str, has_attachment: bool = False,
             max_chars: int = 160, max_words: int = 28) -> str:
    """判定序：附件 → 空文本 → 代码块 → 强关键词 → 多段 → 长度 → 弱信号区。"""
    text = text.strip()
    if has_attachment:
        return STRONG                       # 1) 图片/文档：本地多模态弱，硬上强模型
    if not text:
        return SIMPLE                       # 2) 空文本：工具链延续，走便宜侧
    if "```" in text:
        return STRONG                       # 3) 代码块：任务型
    if STRONG_EN.search(text) or any(kw in text for kw in STRONG_ZH):
        return STRONG                       # 4) 强关键词（优先级高于长度）
    if paragraphs(text) >= 2:
        return STRONG                       # 5) 多段落
    char_len, words = len(text), len(text.split())
    if contains_han(text):                  # 6) 中文无空格分词：词数×2 折算汉字阈值
        zh_limit = max_words * 2
        if char_len > zh_limit:
            return STRONG
        if char_len >= zh_limit * 3 / 4:
            return UNSURE
        return SIMPLE
    if char_len > max_chars or words > max_words:
        return STRONG
    if char_len >= max_chars * 3 / 4 or words >= max_words * 3 / 4:
        return UNSURE                       # 7) 弱信号区：接近阈值但无强信号
    return SIMPLE

ARBITRATE_PROMPT = ("你是路由器。判断用户请求属于哪类：简单（一句话直接能答、或继续刚才的操作）"
                    "还是复杂（需要写代码、多步骤处理或深度思考）。只回答一个词：简单 或 复杂。")

class SmartRouter:
    """级联路由器：simple/strong/arb 三个槽位各配 (endpoint, api_key, model)。"""

    def __init__(self, simple: tuple, strong: tuple, arbitrate: tuple | None = None,
                 max_chars: int = 160, max_words: int = 28):
        self.slots = {"simple": simple, "strong": strong, "arb": arbitrate or simple}
        self.max_chars, self.max_words, self._cache = max_chars, max_words, {}

    def _chat(self, slot: tuple, system: str, user: str, timeout: int = 8) -> str:
        endpoint, key, model = slot
        try:
            r = requests.post(
                f"{endpoint.rstrip('/')}/chat/completions",
                headers={"Authorization": f"Bearer {key}"},
                json={"model": model, "temperature": 0, "max_tokens": 512,
                      "messages": [{"role": "system", "content": system},
                                   {"role": "user", "content": user}]},
                timeout=timeout)
            r.raise_for_status()
            return r.json()["choices"][0]["message"]["content"] or ""
        except Exception:
            return ""                        # 任何失败：空串（调用方归 simple）

    def _arbitrate(self, text: str) -> str:
        key = hashlib.sha1((self.slots["arb"][2] + "\x00" + text).encode()).hexdigest()
        if key in self._cache:
            return self._cache[key]
        ans = self._chat(self.slots["arb"], ARBITRATE_PROMPT, text)
        decision = STRONG if "复杂" in ans else SIMPLE
        if len(self._cache) > 1024:
            self._cache.clear()
        self._cache[key] = decision
        return decision

    def resolve(self, text: str, has_attachment: bool = False) -> tuple[str, str]:
        """返回 (model, decision)。塌缩规则：simple 槽缺位 → 升级 strong。"""
        d = classify(text, has_attachment, self.max_chars, self.max_words)
        if d == UNSURE:
            d = self._arbitrate(text) if self.slots["arb"] else SIMPLE
        model = self.slots["strong"][2] if d == STRONG else self.slots["simple"][2]
        if d == SIMPLE and not self.slots["simple"]:
            model, d = self.slots["strong"][2], STRONG
        return model, d

    def chat(self, text: str, has_attachment: bool = False) -> str:
        """按路由结果回答（强/简单槽各用各自端点；超时 120s 适配本地大模型）。"""
        model, _ = self.resolve(text, has_attachment)
        slot = next((s for s in self.slots.values() if s[2] == model), self.slots["strong"])
        return self._chat(slot, "", text, timeout=120)


if __name__ == "__main__":
    # 本机实测配置：双 2080 Ti 22G，本地 35B 在 8099 在线；云端 DeepSeek 兜底
    LOCAL = ("http://127.0.0.1:8099/v1", "local-noauth", "ornith-1.5-35b")
    CLOUD = ("https://api.deepseek.com", "<your-api-key>", "deepseek-v4-flash")
    router = SmartRouter(simple=LOCAL, strong=CLOUD, arbitrate=LOCAL)

    for q in ["帮我优化这段代码的性能", "这句话是什么意思？"]:
        model, decision = router.resolve(q)
        print(f"[{decision:6s}] {model}  <-  {q}")
```

### 使用与移植要点

- **判定序不可乱**：附件 → 空文本 → 代码块 → 强关键词 → 多段 → 长度，前者命中即短路；强关键词优先级恒高于长度。
- **所有失败归 simple**：仲裁超时/端点失联/解析失败都走便宜侧——路由器绝不能成为新的故障点。
- **仲裁缓存键含判定模型名**：切换仲裁模型后旧结果自动失效；缓存上限 1024 整体清空即可。
- **塌缩规则**：`simple` 槽缺位 → 升级 `strong`；`strong` 槽缺位 → 整体不路由（保持调用方原模型）。
- **阈值调优**：中文短句居多时先把 `max_words` 调大（更多轮留在本地），观察质量回退再收紧。
- 按本机对照：`simple` 与 `arb` 都填 `ornith-1.5-35b`（8099，在线免费），`strong` 填 DeepSeek——即得到「简单免费 → 复杂才花钱」的完整级联。
